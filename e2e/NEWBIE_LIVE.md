# E2E против настоящей базы: проект `newbie-live`

Три сценария нового пользователя идут в БОЕВУЮ базу Supabase под тестовыми аккаунтами владельца (без заглушки сети,
в отличие от проекта `newbie`). Запуск — только на GitHub Actions: workflow `.github/workflows/newbie-live.yml`.

## Как запускать
- Actions → «Newbie live» → Run workflow (кнопка видна, когда файл workflow лежит в `main`);
- или пушем в `claude/cool-euler-bb396v` с меткой `[live]` в сообщении коммита.
- Результат — артефакт `newbie-live-evidence` (html-отчёт, видео и трассы, 14 дней). Каждый сценарий кладёт в отчёт вложения
  `итоги` (json) и `manual: …` (что боевое наполнение не дало проверить).
- Локально без секретов проект просто пропускает тесты: `npx playwright test --project=newbie-live`.

## Секреты репозитория
`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (те же, что у гостевого job), `E2E_USER_EMAILS` (три адреса через запятую),
`E2E_USER_PASSWORD` (три пароля через запятую в том же порядке, либо один общий без запятых; пароль с запятой не поддерживается).
Необязательный `E2E_LIVE_TURNSTILE_SITE_KEY` — ключ виджета капчи.

## Аккаунты
| № | Сценарий | Файл |
|---|---|---|
| 1 | новичок, вошёл до начала: сброс → лента → вопрос Пита → игра → «Сохранить слово» → «Память» → рассказ → «Когда удобно» 20:00 | `newbie-live-user.spec.js` |
| 2 | гость → лайк → вход (перенос в `module_likes`) | `newbie-live-guest-login.spec.js` |
| 3 | второй день: слова уже в памяти, «Память» сразу, «Напоминание: 20:00», «Скажи вслух» | `newbie-live-day2.spec.js` |

Устройство каждого аккаунта: `localStorage.pithy_anon_id = 'e2e-live-<n>-<номер прогона>'`. Dev-сервер стенда события аналитики
в базу НЕ отправляет (`track.js`: отправка только в сборке), а миграция `20261028100000_analytics_exclude_e2e.sql` на всякий случай
исключает `anon_id like 'e2e-%'` из `analytics_report` и `analytics_prompt_groups`.

## Что сбрасывается у аккаунта (и что нет)
Клиенту RLS разрешает: читать свои `word_memory`/`user_profiles`/`module_likes`, писать свои `module_likes`, звать RPC
(`set_remind_time`, `memory_seed_word`, `set_level_profile`, `set_prompt_group`). Писать в `word_memory` и профиль напрямую нельзя.
- Всегда: удаляются свои `module_likes`; выключается напоминание (`set_remind_time(null, false)`).
- Только после миграции `20261028110000_e2e_reset_me.sql` и внесения адресов в `app_settings.e2e_accounts`: RPC `e2e_reset_me()`
  удаляет `word_memory`, `review_events`, лайки и обнуляет `remind_*`, `ear/vocab_level`, `prompt_group`. Без неё сценарий №1
  не может вернуть аккаунт в «новичка»: пишет `manual` и проверяет то, что возможно (после первого прогона вкладка «Память»
  уже не скрыта).
- НЕ сбрасывается никогда: `tz`, XP, серия, пройденные уроки, покупки, достижения, события в `app_events` (по `anon_id` их можно отличить).

## Капча Supabase
Стенд входит БЕЗ токена Turnstile (`VITE_TURNSTILE_SITE_KEY=''`). Если в Supabase (Authentication → Attack Protection) капча включена,
вход вернёт отказ «captcha», и тест упадёт с этим текстом. Варианты: на время прогона выключить капчу; либо задать секрет
`E2E_LIVE_TURNSTILE_SITE_KEY` (виджет попробует пройти сам — в headless это не гарантировано). Node-часть (`liveClient`) входит
паролем напрямую и упирается в ту же капчу.

## Безопасность артефакта
Репозиторий публичный, а трасса Playwright пишет ввод в форму и тела запросов. Поэтому: (1) в конце каждого сценария гасятся все
сессии аккаунта (`signOut global`) — токены в трассе мёртвые; (2) `scripts/e2e-scrub-evidence.sh` до загрузки заменяет в трассах
пароли, адреса и JWT на `***`; (3) видео остаётся как есть — в нём виден набираемый адрес (пароль точками). Заведите для тестов
отдельные адреса, не личные.

## Что не проверяется даже с настоящей базой
Реальные пуши (отправка и приём), озвучка Пита на слух и распознавание речи (Vosk, микрофон), реальный iPhone/Safari и слабые
устройства (Galaxy A50), производительность при троттлинге CPU, оплата, админка, поведение при плохой сети; игра «Выбери слово»
зависит от боевого наполнения и бюджета шторок Пита — если не выпала, сценарий пишет `manual` и кладёт слово в память RPC.
