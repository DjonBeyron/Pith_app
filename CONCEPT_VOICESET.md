# Запись набора (стенд пилюль, v3.3.188)

Зачем: до сих пор распознавание мерили только на синтезированной речи (espeak). Владелец предложил наговорить слова своим голосом «в разных незаконченных режимах», чтобы на них
ставить настоящие эксперименты. Здесь две части: **(А)** режим стенда пилюль, которым за 15–20 минут записывается набор клипов через тот же путь звука, что в игре, и отдаётся
архивом; **(Б)** прогонщик, который подаёт архив в настоящий Vosk и настоящие слушатели игры и печатает таблицу. Настройка распознавания по записям — отдельная работа.

## А. Режим «🎙 Запись набора»
Вход — кнопка «🎙 Запись набора» на панели стенда пилюль (рядом с режимом). Экран поверх стенда (`features/pillstand/voiceset/`, отдельный ленивый кусок сборки); пилюля и слушатель
стенда на это время стоят (`PillStand.jsx`: `paused`).

### Сценарий (`voiceSetPlan.js`, порядок детерминированный)
1. **Тишина 20 с** (первой: она же — «подложка» прогонщика).
2. **Слова**, сгруппированы по слову: вид за видом, повторы подряд. Слова по умолчанию: house, nice, milk, from, tree, book, cat, dog, water, apple, window, breakfast, yesterday,
   together, interesting, wonderful; список редактируется (поле «через запятую», хранится в `localStorage pithy_voiceset_prefs_v1`). Виды:

   | Вид | Задание на экране | При прогоне должно быть |
   |---|---|---|
   | `whole` | целиком, обычным голосом | зачёт |
   | `quiet` | целиком, тихо — как в игре | зачёт |
   | `fast` | целиком, быстро | зачёт |
   | `nolast` | без последнего звука (пример: house → «hou…», milk → «mil…») | нет зачёта |
   | `half` | только начало, примерно половина («inter…», «wond…») | нет зачёта |

   Пример обрубка строится по буквам автоматически — это подсказка человеку, а не эталон. Повторов на вид: 1 / 2 / 3 (по умолчанию 3).
3. **«Не слова»** по разу: кашель, «э-э-э», стук по столу (зачёта быть не должно).
4. **Фразы** «See you later», «I love you», «Nice to meet you»: целиком (чистый зачёт) и с недоговорённым последним словом (чистого зачёта быть не должно).
5. **Обычный фон 20 с.**
6. Флажок **«ещё раз на вытянутой руке»** — блок в конце: `whole` и `nolast` по разу на слово с пометкой `far`; перед блоком запись сама встаёт на паузу (телефон отодвигают один раз).

Итого по умолчанию 251 клип (с far — 283), ≈ 13 минут записи.

### Ход записи — без лишних нажатий (`voiceSetSession.js`)
Задание показывается заранее («приготовься…», 0,7 с; после «Начать» / «Продолжить» и на границе разделов — 2 с) → бежит полоса окна записи (слово 2,2 с, фраза 4 с, «не слово» 3 с,
тишина / фон 20 с — константы `voiceSetPlan.js`) → клип сохраняется → следующее задание. Длина окна считается по отсчётам звука, а не по таймеру. В клип входит **предзапись** —
последние ≈ 0,5 с перед окном (слово, начатое чуть раньше полосы, не теряет начало; прогонщик получает настоящий фон перед словом). Звуков стенд не издаёт.
На экране: прогресс «37 / 251», слово крупно, задание, «скажи: hou…», индикатор уровня и «голос слышно», следующее задание. Кнопки: «Пауза / Продолжить» (прерванный клип
переписывается), «Переписать прошлый» (ближайшее назад записанное или пропущенное задание), «Пропустить», «Закончить». Если за окно голоса не было или слово не уместилось —
жёлтое предупреждение, а следующая пауза длиннее (2,6 с): есть время нажать «Переписать прошлый» (у тишины и фона проверки нет).

### Звук — тот же путь, что в игре (`voiceSetCapture.js`)
- Поток — игровой (`gameMic.js`: те же ограничения getUserMedia — без эхо- и шумоподавления, с автоусилением системы), контекст — контекст захвата игры (`voskCapture`, родная частота),
  куски по 2048 кадров, как у слушателя слов. Снимаются сырые отсчёты (не MediaRecorder).
- В WAV пишется **сырой поток** (до «Чувствительности микрофона»), моно, 16 бит, **16 кГц** с ФНЧ (`voiceSetWav.js`: полифазный КИХ, полоса до ≈ 6,9 кГц ровная, зеркал нет, уровни
  не меняются). Исходная частота (48 кГц) дала бы ≈ 70 МБ на набор; 16 кГц — ≈ 23 МБ (с far ≈ 26 МБ). Vosk всё равно пересчитывает звук в 16 кГц.
- Тем же узлом, отсчёт в отсчёт, снимается второй канал — после «Чувствительности микрофона» игры (`voskGain.wireInput`: GainNode ×2 + ограничитель). Это уровень, который видит
  слушатель; по нему счётчик `voskVoice.js` считает длительность голоса. Автоусиление `voskAgc.js` к записи не применяется (оно в движке — работает при прогоне).
- Числа каждого клипа меряются на ИСХОДНОМ звуке (`voiceSetMeter.js`) и идут в манифест: `rmsPeak`, `rmsNoise` (сырой поток), `gamePeak`, `gameNoise` (после усиления игры),
  `voiceMs`, `voiceOnMs`, `voiceOffMs`, флаги `noVoice` / `late` / `early`, `clipped`, и **огибающая** `env` — rms × 1e6 каждого куска исходного звука (`chunkMs` — длина куска).

### Надёжность на iPhone
- Клип сразу пишется в IndexedDB `pithy_voiceset_v1` (`voiceSetStore.js`: запись клипа и байты WAV одной транзакцией). Перезагрузка / звонок набор не теряют: при входе —
  «Продолжить набор (сделано 120 из 251)» / «Собрать архив» / «Начать заново». Нет IndexedDB — память страницы и предупреждение.
- Экран не гаснет (Wake Lock, `voiceSetWake.js`); страница ушла в фон — пауза.
- Микрофон: механика здоровья стенда (`useStandMicHealth`): дорожка заглушена / оборвана, уровень ровно 0 дольше 2 с, а также «звук перестал приходить» (контекст захвата прерван —
  сторож 1,5 с) → запись на паузе, стенд пробует оживить сам, не вышло — красная плашка «Микрофон отключился — нажми, чтобы включить» (getUserMedia в нажатии). Клип с ровным нулём не
  сохраняется; прерванный клип переписывается. Сбои микрофона попадают в манифест (`micEvents`).

### Архив
«Собрать архив» → ZIP без сжатия (`voiceSetZip.js`: свой писатель «store» с CRC-32, без библиотек): `manifest.json` + `clips/NNN_слово_вид_повтор.wav` (far — `…_whole-far_1.wav`).
Больше ≈ 20 МБ — части «часть 1 из N», каждая — самостоятельный ZIP со своим манифестом. Архив собирается заранее, а отдаётся кнопкой части: «Поделиться» на iPhone открывается только
прямо из нажатия (`saveDebugFile`: iPhone — «Сохранить в Файлы», иначе новая вкладка; компьютер — скачивание). После выгрузки набор остаётся на устройстве до «Удалить набор».
Манифест: `kind: 'pithy-voiceset'`, версия приложения, устройство и UA, даты, настройки набора, `audio` (частота WAV и контекста, предзапись, micGain), `constraints` и
`track` (`track.getSettings()`), `captures` (каждое открытие захвата: время, версия, частота, дорожка), `skipped`, `micEvents`, `clips` (см. выше + `file`, `word` / `phrase` / `id`,
`variant`, `rep`, `far`, `expect`, `ms`, `preMs`, `sampleRate`, `srcRate`, `bytes`, `t`).

### Как записать набор (владельцу)
1. Открыть стенд пилюль (как обычно) → «🎙 Запись набора».
2. При желании поправить слова и число повторов → «🎙 Начать запись», разрешить микрофон. Телефон держать как в игре.
3. Читать задание и говорить, когда побежит красная полоса; дальше стенд идёт сам. Ошибся — «Переписать прошлый»; отвлекли — «Пауза».
4. Можно закрыть страницу и вернуться позже: «Продолжить набор».
5. В конце (или по «Закончить») — «📦 Собрать архив» → нажать «Сохранить часть 1…» → «Сохранить в Файлы»; так же вторую часть.
6. Отправить .zip-файлы. «Удалить набор» — когда файлы дошли.

## Б. Прогонщик `scripts/voice-set-run.mjs`
```
node scripts/voice-set-run.mjs набор-part1of2.zip набор-part2of2.zip --model путь/vosk-model-small-en-us-0.15.tar.gz --out папка [--repeat 3] [--jobs 3]
```
Распаковывает архив(ы), сам поднимает dev-сервер Vite и Chromium (Playwright), открывает `_stand/voice_set/index.html` и подаёт клипы подряд в одну сессию (модель грузится один
раз на вкладку): слово → `wordLaneListen.js` с правилом честного зачёта (как вертикальная пилюля: цель — одно слово, expected 1, maxWords 2), фраза → `racePhraseListen.js`
(`--phrase-pass 1|2`), тишина / фон / «не слова» → слушатель слов с целями-пробами (`--probes house,nice`). Пишет `results.json` (по клипу: зачёт, момент, «конец голоса → зачёт»,
черновики, итоги с conf и «кто закрыл», строки `[word-ear]` / `[phrase-ear]`, затвор, усиление, уровни) и `table.txt` (`voiceSetTable.js`): по видам, по словам, провалы, сверка
уровней. Замер: 40 клипов — 4,3 мин в одну вкладку, 2 мин в три (`--jobs 3`); полный набор (282 клипа, две части архива) — 6,5 мин в три вкладки (в одну — ≈ 20 мин).

**Как подаётся звук.** Один AudioContext страницы → MediaStreamDestination = «микрофон» (поток отдаётся слушателю как готовый поток игры). Клип играется как записан, громкость не
нормируется. Между клипами в поток идёт **подложка** — тишина из самого набора по кругу (настоящий шум того же микрофона): слушатель не видит ровного нуля и оценивает шум, как в
игре (`--no-bed` — без неё). Усиление — как в игре: «Чувствительность микрофона» (`--mic-gain`, по умолчанию из манифеста) → затвор → автоусиление движка.

**Поправка тракта — откуда «×3,3» и что с 16 кГц.**
- Фальшивый микрофон амплитуду не меняет. «Усиление ≈ ×3,3 у стенда» — это «Чувствительность микрофона» игры: GainNode ×2 и **компенсирующее усиление ограничителя**
  (`DynamicsCompressor` всегда добавляет makeup gain, при пороге −10 дБ и ratio 20 — ≈ ×1,7; сам сигнал ниже порога не сжимается). Замер: `gamePeak / rmsPeak` = ×3,3…×3,6. Поэтому в
  наборе хранится сырой звук, а уровень после усиления — отдельным числом; при прогоне усиление делает сам слушатель. Проверка `--mic-gain 1`: уровень движка = сырой.
- Хранение в 16 кГц срезает всё выше 8 кГц, а слушатель меряет громкость куска по всей полосе: шум микрофона и шипящие вышли бы тише (белый шум — ×0,6), сдвинулись бы порог голоса и
  автоусиление. Поэтому прогонщик по огибающей `env` из манифеста возвращает каждому куску недостающую мощность **шумом выше 9,5 кГц** — Vosk его не слышит (сам пересчитывает звук в
  16 кГц), а счётчик голоса, затвор и автоусиление видят исходную громкость (`--no-hf` — без поправки). Шум детерминированный.
- Сверка (тестовый набор: espeak через фальшивый микрофон, 282 клипа): rms всего клипа вход / манифест — медиана ×0,99 (5–95 %: ×0,97…×1,00; вне ±10 % — 0 из 282); фон — ×1,00;
  уровень движка без усиления (`--mic-gain 1`, rms клипа) — ×1,01 (×1,00…×1,03); пик после усиления игры — ×1,00 (×0,91…×1,08). Пик ОДНОГО куска гуляет до ±10 % (за пределы выходят
  ≈ 6–9 % клипов): он зависит от того, как куски по 2048 кадров легли на слово, — поэтому главная строка сверки — rms всего клипа.

**Повторяемость.** Подача идёт в реальном времени, границы кусков каждый раз ложатся по-своему — пограничный клип может сработать по-разному (espeak «milk»: Vosk слышит то «milk»,
то ловушку «mill»). `--repeat N` прогоняет каждый клип N раз; таблица показывает раздел «Устойчивость» — какие клипы срабатывают не во всех повторах.

## В. Постоянная регрессия на живых голосах (v3.3.190)
`tests/voice-sets/novice-1.zip`, `novice-2.zip` — два набора по 91 клипу (iPhone, v3.3.189, голоса двух начинающих; по 9,6 МБ). `baseline.json` — «верно / всего» по видам клипов каждого набора.
```
node scripts/voice-set-regress.mjs --model путь/vosk-model-small-en-us-0.15.tar.gz [--chrome ПУТЬ] [--reuse] [--update]
```
Гонит оба набора по очереди через прогонщик (≈ 6 мин) и сверяет с линией: «верно» по виду не должно стать меньше (выход 1 — регрессия). `--update` — записать новую линию после осознанного улучшения.
Линия на 2026-11-12 (набор 1 / набор 2): целые 16/16 · 16/16, быстрые 16/16 · 16/16, тихие 15/16 · 15/16, шум 3/3, тишина 2/2, целые фразы 3/3; «без последнего звука» 12/16 · 10/16, «половина» 14/16 · 15/16,
фразы без последнего слога 0/3 · 0/3 — это предел малой модели (Vosk достраивает «ca»→«cat», «yo»→«you»; признаки конца слова — спад, ступенька, высокие частоты, длина — целое от обрубка не отличают, замер на 64 словах двух голосов).
Дополнять набор новыми голосами: положить `*.zip` в `tests/voice-sets/` и запустить с `--update`. В наборах — голоса людей, репозиторий приватный.

## Ограничения (на 2026-11-11)
- На настоящем iPhone не проверено: «Поделиться» файлом .zip на 20 МБ, Wake Lock, квота IndexedDB (≈ 26 МБ набора), поведение при звонке / Siri (сторож и плашка проверены только
  подменой потока в Chromium), совпадение makeup gain ограничителя Safari и Chromium (если разойдётся — в сверке уровней «движок / gamePeak» медиана уйдёт от ×1; поправить `--mic-gain`).
- Счётчик голоса при записи идёт непрерывно, а в игре у каждого захода свой — `voiceMs` манифеста и прогона могут расходиться на кусок-другой.
- Клип хранит полосу до 8 кГц: выше — только уровень (огибающая), не сам звук.
- Результаты прогона на espeak-наборе (например, «half» засчитан 9 из 48, «milk тихо» — 0 из 3) — свойство синтетических клипов (обрезка волны пополам, робот-голос), а не вывод о
  распознавании: для выводов нужен набор владельца.
