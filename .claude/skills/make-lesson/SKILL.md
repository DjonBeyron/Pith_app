# make-lesson — надёжная сборка урока

Правила — источник правды: `lesson-drafts/rules.json` (выгрузка из окна правил). Если файла нет — берётся стандартный набор из кода (`src/features/canvas/lesson-io/rules/*.js`, тот же, что кнопка «Синхронизировать со стандартом» кладёт в базу) — это нормально, пока пользователь не правил правила в окне.

## Шаги (строго по порядку, не пропускать)
1. **Промпт**: `node scripts/lesson-prompt.mjs "<тема>"` — прочитай целиком: формула, правила R1…Rn, формат нод. Это твоё ТЗ, не пересказывай его из памяти.
2. **План** (в чат, коротко): части урока; в каждой — что ученик замечает / делает сам / чем усложняется. Покажи пользователю и дождись «го», если урок новый и большой.
3. **Урок**: напиши JSON в `lesson-drafts/<имя>.json` (образец структуры: `lesson-drafts/trying.v2.json`, заметки `src/features/canvas/lesson-io/AUTHORING_NOTES.md`). Для больших уроков удобнее скрипт-генератор в scratchpad, не в репо. Выделения — ТОЛЬКО разметкой `{g:..}` `{w:..}` `{u:..}` `{b:..}` `{p:..}`, массив `highlights` не пиши. Нужны `ref`, `type`, `seq`, `pos`, `triggers`.
3а. **Сцены** (только в уроках-словах, не в Старте/Финале): вставляй по группе правил «Сцены» (S1–S8 в промпте шага 1): открывающий и закрывающий кружок Пита (`mode: "circle"`, один кот `a`), в середине диалог двух котов (`bubble`), 2–4 сцены, без `task`. Формат и образцы — в `AUTHORING_NOTES.md` («Сцены в уроке»). Каждую сцену сначала проверь: `node scripts/lint-scene.mjs <сцена.json>`. `audioUrl` не придумывай: реплики без него озвучивает админ в сборщике (шлюз покажет их как `needsVoice`).
4. **Шлюз**: `node scripts/lesson-gate.mjs lesson-drafts/<имя>.json --fix-seq`. Пока есть замечания — исправляй урок и запускай снова (до 5 кругов). Шлюз ловит формат, ритм (R-text-run, R-tautology), say_phrase, ответы, подсветки.
5. **Судья по группам**: `node scripts/lesson-prompt.mjs --judge-groups` даёт список групп (≈10). Запусти агента `pithy-lesson-judge` (Agent, subagent_type `pithy-lesson-judge`) **на каждую группу отдельно, все параллельно в одном сообщении**, передав путь к файлу и название группы. Один судья на все правила сразу — нельзя: на сотне правил он теряет «правила по всему уроку». Собери JSON нарушений всех групп. Исправь урок по каждому `ok:false` (если судья ошибся — зафиксируй причину в отчёте, не спорь молча). После правок снова шаг 4, затем судьи ещё раз (можно только по группам, где были нарушения). Максимум 3 круга судьи.
5а. **Образцы**: если есть `lesson-drafts/examples.json` (окно «Разбор» → «⭐ Набор» → «Скачать examples.json»), промпт шага 1 сам добавит раздел «ОБРАЗЦЫ ИЗ ЗОЛОТОГО НАБОРА» — пиши в духе ✅-примеров, это важнее, чем ещё раз перечитать правила.
6. **Отчёт пользователю** (коротко, по-русски): сколько нод/зон; что осталось озвучить/загрузить руками (список из шлюза); какие замечания судьи не исправлены и почему; путь к файлу. Не заявляй «всё чисто», пока шлюз и последний круг судьи не пройдены — если что-то осталось, скажи прямо.

## Нельзя
- Отдавать урок, не пройдя шаги 4 и 5.
- Выключать/обходить правила, чтобы пройти шлюз (в т.ч. править `rules.json` ради прохождения).
- Придумывать файлы озвучки/фото: для новых — `needs` / `needsVoice` и `imagePrompt`, как в легенде.
- Пушить в git без явной просьбы пользователя.
